# v0.6 diagnostics and field service

Version: **0.6.0-beta.1**. These tools extend the existing application; they do not start a separate web server, require a cloud account or install packet-capture drivers.

Open **Commissioning → Diagnostics & service**, choose a saved site/device, then choose a tool. Saved-site device context menus also offer **Troubleshoot connection**, **Inspect security** and **Equipment label**. Save a discovered or routed camera into a site to retain results and use its assigned credentials. Network probes run only when requested. The common task banner shows progress and cancellation; Live View remains a separate window.

## Implementation map

The repository already supplied discovery/inventory, SQLite documents/assets, protected credentials, trusted SSH probes, ONVIF/ISAPI transports, NVR mappings, native RTSP playback, snapshots, commissioning reports and shared job cancellation. The implementation reuses those components. Generic versioned documents keep the schema at v3; no destructive database migration is needed. Existing schema migration tests and portable-backup tests remain applicable.

The roadmap explicitly gates firmware/replacement write adapters until hardware validation, permits manual imaging where capabilities are absent, and requires actionable unsupported recording retrieval. Those boundaries remain visible in the UI. No placeholder claims of firmware upgrades, privacy-mask enforcement, decoded replay or VMS delivery are made.

## Connectivity

Choose the source adapter (or OS route), comma-separated TCP ports and probe timeout. HTTP/HTTPS probe ports must be in that port list. ICMP permission failure leaves the other checks usable. A source address binding does not override the workstation routing table. For a routed camera, absence of its MAC in the local neighbour table is expected.

Windows destination detail uses `GetBestRoute2`. Linux optionally uses `ip -j route get` with a validated numeric destination/source; missing iproute2 leaves a clear unknown next hop. Both retain the normal Go socket route/source check. No elevated command is used.

Authenticated reads use the selected camera's assigned credential and existing certificate fingerprint trust. The basic TLS probe deliberately reports OS certificate trust separately; an explicit ONVIF pin does not imply that Windows trusts that certificate generally. RTSP DESCRIBE resolves a camera-advertised profile, authenticates only to the selected numeric target and never issues SETUP/PLAY.

For SSH comparison, first register and trust the host under **Remote discovery**, install the new CLI there, then select that saved target in the troubleshooter. The versioned capability/envelope exchange rejects an old CLI or a response for a different camera. SSH keys/passwords remain in their existing protected storage.

```sh
make cli
./bin/sadptools --version
./bin/sadptools troubleshoot --ip CAMERA_IP --timeout 2s --ports 80,443,554,8000
./bin/sadptools troubleshoot --ip CAMERA_IP --json
./bin/sadptools troubleshoot --ip CAMERA_IP --interface ADAPTER --report
```

Exit status: 0 checks completed without a failed step (unknown/unsupported still require review), 3 a diagnostic step failed, 2 invalid arguments, 1 execution/output failure, 130 cancellation. `--report` is a versioned remote envelope; `--json` is the diagnostic run itself. No camera credential CLI argument is introduced.

## Recordings, imaging and maintenance

Recording tracks and live stream IDs are not necessarily interchangeable. Select the recorder and use the actual recording track shown by its configuration/API. Existing **NVR channels** supplies saved channel/linked-camera context. Enter an ISO-8601 start/end including `Z` or an explicit UTC offset. Results normalize to UTC; timestamps without an offset are ambiguous and cannot support gap claims. Inspect storage and clock payloads and check recorder playback before signing off recording.

Read imaging capabilities before opening a change preview. The preview names the model, IP, serial, setting, current value and advertised bounds. Confirm `APPLY <serial>`. Only a matching readback is verified. After an uncertain outcome, reread first; do not assume no change occurred. The saved `image-change` evidence records previous/proposed values and outcome. To restore, reread the same profile and explicitly apply its recorded previous value. Live View → Focus & alignment captures Before/After pictures with capture timestamps, codec, resolution and optional manual settings/lighting notes. Snapshots are opt-in and removable from site evidence.

Replacement starts by saving both old and replacement identities to the same site. Review the plan and dependencies, use the existing activation/network/configuration screens as required, rediscover/reconcile the replacement, then run preflight. Successful identity/connectivity verification expires after five minutes. Completion requires exact replacement identity and operator notes covering stream/NVR/recording checks. It retires the old inventory entry and preserves both histories; it does not rewrite historic NVR links. On uncertainty, retain the plan and its manual checklist.

Firmware import hashes the chosen regular file without retaining or uploading firmware bytes. Enter exact official compatibility metadata and documented intermediate builds. **Read device identity** can supplement saved discovery with available hardware identifiers; absent platform/region remains unknown. A checksum proves file consistency against the supplied checksum, not vendor authenticity. Signature verification is explicitly unknown.

## Evidence and privacy

Completed/cancelled field runs are saved as site documents. Use **Saved evidence** to view, preview/export or delete them; report references can prevent deletion. Historic imaging results are read-only previews. Add diagnostic, imaging-change or ANPR assessment documents to commissioning reports using the existing checklist/report flow.

Support bundles cache the exact preview. Changing the selection requires another preview. Normal contents are `device.json`, `adapters.json`, bounded `logs.json`, selected evidence JSON, `manifest.json` and `SHA256SUMS`. Optional screenshots appear with a pixel preview, filename, hash and sensitivity warning. Image metadata is normalized away; visible faces, plates and text remain and require explicit approval. Selected-device anonymisation is not a promise to remove every other customer's identifier from a log or response: review every file.

A local passphrase of at least 12 characters uses the existing authenticated Argon2id/AES-GCM backup format; the output is `.zip.sadpencrypted`. **Decrypt an existing bundle** saves a standard ZIP at a location you choose. No service receives either file automatically. The in-memory preview is replaced on the next preparation and discarded on shutdown; exported files remain where you chose until you delete them.

Raw trace capture is a separate opt-in file, at most 60 seconds / approximately 8 MiB, on one named adapter with a `host <selected-IP>` capture filter. It disables promiscuous capture and uses a private temporary file. Cancellation/error removes that file. A successful trace is kept only at the chosen destination. Never assume its packets are scrubbed. Metadata bundles work when dumpcap is absent.

## Components and sources

- `internal/diagnostics`: structured results, bounded network probes, scrubber, firmware hashes, labels, support ZIP/encryption and optional trace orchestration.
- `internal/platform/route_detail_*`, `capture_*`: Windows/Linux route and capture adapter integration.
- `internal/recordings`, `internal/isapi/recordings.go`, `internal/onvif/{recordings,imaging,inspect,anpr}.go`: protocol adapters and evidence semantics.
- `internal/sites/replacement.go`: persistent plan and atomic retirement; existing generic documents/backups retain all new evidence types.
- `internal/toolkit/{field,maintenance}.go`, `desktop_field.go`, `frontend/src/field-service.js`: orchestration, Wails bindings and presentation. Networking remains independent of Wails.
- `internal/cli/troubleshoot.go`, existing `internal/remote`: standalone and comparative diagnostics.
