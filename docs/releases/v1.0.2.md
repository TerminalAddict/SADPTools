# SADPTools v1.0.2 — encrypted camera activation

Fixes the activation path that sent an incomplete request and could leave a
camera inactive while reporting **No conclusive reply**.

- Activation now checks that the selected camera is still inactive, negotiates
  its SADP encryption key, and sends the encrypted password once through the
  discovered adapter. There is no automatic retry or plaintext fallback.
- Valid activation replies that omit the MAC address are accepted only when
  their source address, receiving adapter, request UUID and operation type match
  the verified transaction. Conflicting identities are rejected.
- Preparation failures explicitly say **Activation was not sent**. Missing final
  acknowledgements still require rediscovery and password verification.
- Camera responses for weak passwords and already-active devices now produce
  useful messages. The activation dialog explains the exchange and supported
  **8–16 UTF-8 byte** password limit; longer passwords are never truncated.
- Desktop, CLI and provisioning operations share the corrected Go engine.

## Windows downloads

For an existing standalone installation, download
**SADPTools-1.0.2-standalone-windows-amd64.zip**, close SADPTools, extract the ZIP
and run **SADPTools-windows-amd64.exe**. Existing saved sites and protected
credentials remain in the user's configuration directory.

For an installed copy or a new computer, use
**SADPTools-1.0.2-Setup-windows-amd64.exe**. The installer includes the offline
display runtime. The in-app updater can also install this release.

Linux DEB/RPM/manual packages, universal Apple Silicon + Intel Mac DMG/ZIP,
Windows/Linux CLI archives, checksums and build provenance are included.

## Validation and limits

Read-only investigation of an IPC-B261H-MU running V5.7.1 build 220610 confirmed
inactive status and the encryption/reply format. The corrected Go preparation
path successfully completed its inquiry, identity checks and key exchange
against that camera. A transport guard blocked the activation datagram before
it reached the network. **No activation or password change was performed during
that validation; successful activation and login still need a Windows field
test.** No real credentials, challenges or device identifiers are included.

Release checks cover Go tests/vet/race, frontend tests/build, packaging tests,
native Windows/Linux/Apple Silicon/Intel CI, universal Mac bundle validation,
and SHA-256 verification of every uploaded asset. Synthetic tests cover the
encryption vector, correlation, malformed challenges, explicit rejections,
cancellation, transport errors, lost acknowledgements and socket cleanup.

Windows builds remain unsigned. Mac bundles use ad-hoc signatures without
notarization. Other camera operations retain their existing firmware and
hardware-validation limits. An unconfirmed write must never be treated as
proof that no change occurred.

See the [activation guide and protocol limits](https://github.com/TerminalAddict/SADPTools/blob/v1.0.2/docs/device-management.md).
