# SADPTools v0.4.0-beta.2 — Live View

Live View now opens in its own desktop window and starts playback automatically.
Keep using discovery, saved sites and the rest of SADPTools while watching a
camera. This release includes the initial Live View implementation and its
window and login improvements; beta.1 was a local test build only.

## Changes

- Open Live View from a discovered camera, saved device or device context menu.
  The sub stream starts automatically. When a login is needed, **Sign in and
  view** starts playback immediately, without another Play click.
- Move and resize the separate viewer independently. Reopening the same camera
  focuses its window; choosing another camera replaces the single live stream.
  Closing the main app also closes the viewer and its connection.
- Pause/resume reuses session credentials held in Go memory. Closing the viewer
  or explicitly locking saved passwords clears them. Session logins are not
  saved to disk.
- Saved passwords remain encrypted. Windows makes them available automatically
  through the signed-in account. **Lock now** remains optional and blocks access
  until explicitly unlocked or the app restarts. Linux still asks for its master
  passphrase when saved credentials are needed. Active playback keeps its saved
  credentials in use instead of expiring them as idle.
- Read-only ONVIF profiles, Hikvision channel/port selection, custom RTSP/RTSPS,
  HTTP MJPEG and snapshot refresh are available. H.264 is the primary video
  format; H.265 depends on the installed decoder. Audio and recording are not
  included, and the viewer never changes camera encoding or configuration.

## Updating and testing

For an existing standalone Windows app, close it before replacing the EXE with
the one from the new desktop ZIP. Saved sites, credentials and preferences stay
in the current user's configuration directory. Confirm **About** shows
`0.4.0-beta.2`.

The in-app updater also offers this release when beta updates are enabled. It
runs setup and installs the registered app; it does not replace an arbitrary
standalone file. After setup, launch SADPTools from its Start menu shortcut.
Linux users should update through their original package manager or manual
installation method.

Go tests, vet and race checks, frontend tests/build, packaging tests, Windows
cross-compilation and Linux builds are part of release validation. Native Linux
Wails tests under Xvfb displayed synthetic H.264 and H.265 video. Separate-window
navigation, automatic login/playback, pause/resume and native close handling
were checked with a synthetic authenticated H.264 source.

Windows playback, Windows install/update behaviour, physical Hikvision cameras,
HEVC availability and real Linux desktop/Wayland behaviour still need operator
testing. A Windows-only regression test covers automatic DPAPI access in CI;
this does not replace testing saved credentials and playback in the Windows UI.
No physical camera writes were performed. Start camera testing with an H.264
sub stream and follow the [test checklist](https://github.com/TerminalAddict/SADPTools/blob/v0.4.0-beta.2/docs/LIVE_VIEW_TEST_MATRIX.md).

Windows signing remains pending, so SmartScreen may still show Unknown publisher.
Linux packages are also unsigned.
