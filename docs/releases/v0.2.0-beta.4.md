# SADPTools v0.2.0-beta.4

This beta adds security-question password recovery and fixes connectivity checks
for cameras reached through a router.

## Changes

- Select an activated camera and open **Password recovery → Security questions**
  to check firmware support and load its three configured question labels.
  Enter the original answers and a new admin password to submit an encrypted
  reset. Opening the dialog or checking availability does not change passwords.
- Security-question recovery now uses the computer's route to the camera.
  **The camera and computer do not need to share an IPv4 subnet.** Automatic
  selection supports gateways, secondary addresses and VPN adapters; explicit
  adapter overrides are respected. The actual HTTP recovery API response
  determines availability, and connection failures identify the address, port
  and adapter used.
- Added equivalent CLI recovery commands, connection diagnostics and regression
  tests. Credentials are excluded from inventory, preferences and logs. A reset
  is submitted once; missing replies leave its outcome unconfirmed.

## Install or update

Download **[SADPTools-0.2.0-beta.4-Setup-windows-amd64.exe](https://github.com/TerminalAddict/SADPTools/releases/download/v0.2.0-beta.4/SADPTools-0.2.0-beta.4-Setup-windows-amd64.exe)**
for Windows 10/11 AMD64. Setup includes the pinned offline display runtime, so
there is no separate prerequisite download. Windows and Linux CLI archives,
the build manifest and SHA-256 checksums are also included.

From beta.2 or beta.3, enable **stable and beta** updates, then use **About →
Check for updates → Update now**. After setup, confirm About shows
`0.2.0-beta.4`. Beta.1 and `0.2.0-dev` builds require a manual upgrade.

If you run a standalone `SADPTools-windows-amd64.exe`, setup installs into the
registered installation or `%LOCALAPPDATA%\Programs\SADPTools` by default; it
does not replace an arbitrary standalone copy. Launch **SADPTools** from the
Start menu after setup.

## Validation and limits

Release checks cover Go tests, vet and race checks, frontend tests/build,
packaging/release-tool tests, Windows cross-compilation, embedded version checks
and installer integrity. Every uploaded asset is downloaded and verified before
publication. The feature also passed Linux desktop compilation.

Read-only physical-camera checks retrieved configured questions on V5.5.61
firmware and exercised not-configured/unsupported responses on other cameras.
The Linux GUI question workflow was inspected. Encrypted reset and routed
connection tests use synthetic fixtures: **physical-camera password reset/login,
the reported routed Windows connection, and Windows installation/update runtime
behaviour still require validation.** No real passwords were changed during
development or release preparation. Firmware support varies; an unknown question
catalog or encryption exchange prevents submission.

The application and setup remain **unsigned** while the SignPath Foundation
application is pending. Existing SmartScreen warnings may still appear. This
release retains the verified runtime and dependency pins from beta.3.

See the [security-question recovery guide](https://github.com/TerminalAddict/SADPTools/blob/v0.2.0-beta.4/docs/security-question-recovery.md)
for compatibility details, and the [update guide](https://github.com/TerminalAddict/SADPTools/blob/v0.2.0-beta.4/docs/updates.md)
for installation behaviour.
