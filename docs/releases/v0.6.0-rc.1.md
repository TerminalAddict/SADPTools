# SADPTools v0.6.0-rc.1 — Release candidate 1

The first release candidate for the v0.6 desktop and CLI. This promotes the existing advanced-diagnostics build for further testing; application functionality is unchanged from v0.6.0-beta.1 apart from the version stamp. It is a prerelease, not a declaration that every camera model or Windows configuration has been validated.

## Downloads

Windows users should normally choose **SADPTools-0.6.0-rc.1-Setup-windows-amd64.exe**, which includes the offline display runtime. The **standalone-windows-amd64.zip** contains the portable desktop executable and notices; extract it before running and use an existing WebView2 runtime. Linux DEB, RPM and manual tar.gz installers include the desktop application, CLI and application-menu integration. Separate Windows/Linux CLI archives are also attached.

Downloads are also available at [sadptools.com](https://sadptools.com/#downloads). The website automatically follows the newest complete published release, including release candidates.

## Included in this release

- The v0.6 toolkit: discovery and routed camera access; activation, network configuration and authorised recovery; saved sites and credentials; separate-window Live View; commissioning tools and advanced diagnostics. See the [compatibility guide](https://github.com/TerminalAddict/SADPTools/blob/v0.6.0-rc.1/docs/v0.6-diagnostics.md).
- A new cross-platform marketing website with first-party, checksum-verified downloads, Windows installation help, social sharing metadata and structured data.
- A searchable [features catalogue](https://sadptools.com/features.html) covering 36 feature areas, with 72 light/dark screenshots and an accessible full-size viewer. Eight captures show authorised real-camera video; other views use labelled synthetic examples.
- The website distinguishes release candidates from betas and selects RC downloads automatically. Cached screenshots use content-derived versions.

## Validation and release gates

The release builder requires `make check` (Go tests, vet and race detector; frontend tests; Windows/Linux packaging and release-tool tests), a regenerated production frontend, Windows AMD64 desktop/offline installer builds, Linux desktop/CLI and native/manual package builds, installer archive verification and embedded version checks. The source checkout must remain clean throughout the build. Every uploaded release asset is downloaded and SHA-256 verified before publication; the exact source commit and artifact hashes are in `build-manifest.json` and `SHA256SUMS`.

The website passed HTML/CSS validation and desktop/mobile browser checks in both themes, including search, screenshot navigation, focus return, same-origin asset requests and automated accessibility checks. Published screenshot hashes matched the reviewed captures. Proxy tests cover RC ordering and automatic promotion from cached beta metadata.

Read-only physical-camera evidence was collected with the unchanged v0.6 application code on Linux: H.265 sub-stream and 3072 × 2048 main-stream playback, observed stream metrics and preview-only alignment/sharpness tools. Session credentials were not saved. PTZ controls were not queried, armed or operated, and no camera settings were changed. This does not validate other cameras, NVR recording accuracy, imaging writes or Windows playback.

## Still needs hands-on testing

- Windows installer and standalone launch, About showing **0.6.0-rc.1**, upgrade from the previous beta, WebView2 behaviour and camera playback.
- Linux installation/removal on supported distributions and desktop menu integration outside the build host.
- Discovery on multiple adapters and routed networks; authorised activation, network/recovery and imaging operations on identified test devices.
- Supported NVR searches/gaps against recorder playback, events/ANPR, switch/PoE mapping, labels and site handover workflows.

Windows binaries remain unsigned, so an unknown-publisher/SmartScreen warning is still possible. Firmware upload/reboot, automatic replacement provisioning/cloning/NVR reassociation, privacy-mask editing and verified replay retrieval remain unavailable. Review the compatibility guide before device writes; uncertain outcomes are not automatically retried.
