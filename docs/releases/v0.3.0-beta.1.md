# SADPTools v0.3.0-beta.1 — technician toolkit

This beta adds the technician toolkit: persistent sites, protected credentials,
network investigation, commissioning plans and read-only diagnostics.

## New workflows

- **Sites:** persistent inventories, customer/location/installer notes, reusable
  encrypted credentials, inheritance and overrides, encrypted portable backups.
- **IP scanner:** selected adapter, CIDR or range, ICMP/TCP and cached neighbour
  evidence, grid/table views, reservations, cancellation, exports and CLI `scan`.
- **Rescan and review:** saved scan scope, before/after differences, explicit
  acceptance, manual-field protection and persistent change history.
- **Provision:** activation/network previews for selected SADP devices, sequential
  address allocation, conflict checks, explicit approval and per-device results.
- **ONVIF:** additional vendor-neutral multicast discovery, partial identities and
  authenticated read-only information queries where the camera supports them.
- **Audit:** read-only network/service/ONVIF checks with evidence and unknown states;
  customer HTML and technician CSV/JSON reports.
- **Switches:** registered assets, protected SNMPv3 or opt-in v2c credentials,
  FDB/VLAN/LLDP evidence, conservative port mapping and supported PoE observations.

Existing discovery, individual configuration/recovery, branding and update flows
remain available. HTTP/HTTPS detection feeds the device IP link, web launcher and
recovery; separately advertised ONVIF HTTPS ports are included. Scanning displays
progress and cancellation without clearing existing observations.

Windows neighbour-cache access retains the native table pointer through traversal
and cleanup; this also resolves the Windows `go vet` failure found during release
preparation.

## Downloads and saved data

- **[Windows setup](https://github.com/TerminalAddict/SADPTools/releases/download/v0.3.0-beta.1/SADPTools-0.3.0-beta.1-Setup-windows-amd64.exe)** — recommended; includes the offline WebView2 runtime.
- **[Standalone Windows desktop ZIP](https://github.com/TerminalAddict/SADPTools/releases/download/v0.3.0-beta.1/SADPTools-0.3.0-beta.1-standalone-windows-amd64.zip)** — extract and run `SADPTools-windows-amd64.exe`; WebView2 must already be present. Licence notices are included.
- Separate Windows/Linux **CLI archives**, `build-manifest.json` and `SHA256SUMS`
  are provided with the release. The lowercase `sadptools` archives are CLI tools.

On an installed beta, enable **stable and beta** updates, then use **About →
Check for updates → Update now**. The original `0.2.0-beta.1` needs a manual upgrade.

Use setup when the display runtime is not already available. Setup installs under
its registered location or `%LOCALAPPDATA%\Programs\SADPTools`; it does not replace
an arbitrary standalone copy. Confirm **About** shows `0.3.0-beta.1` after launching.

Saved sites and protected credentials live in the current user's SADPTools
configuration directory, independently of the EXE location. Use the encrypted
backup/export features for portability. Windows protection is tied to the current
user account; portable backups use a separate passphrase. Linux uses an explicit
master passphrase. Ordinary exports omit secrets.

## Validation and compatibility

See [validation results](https://github.com/TerminalAddict/SADPTools/blob/v0.3.0-beta.1/docs/validation.md) and the
[implementation guide and hands-on checklist](https://github.com/TerminalAddict/SADPTools/blob/v0.3.0-beta.1/docs/toolkit-implementation.md).
Automated tests and Linux GUI checks use labelled synthetic fixtures. Read-only
live multicast discovery also found SADP and ONVIF responses; these are not proof
of successful configuration, authenticated queries or physical switch mapping.

Bulk provisioning does not retry uncertain writes or promise rollback. A missing
reply may mean the camera changed already. Saved inventory changes require review,
except independently verified provisioning results explicitly approved for saving.
No response from an IP probe does not establish that the address is unused.
ONVIF and SNMP features depend on device support and enabled accounts/services;
unknown PoE power, storage/uptime or firmware upgrade suitability is not invented.

Windows execution/DPAPI/installation/updating, physical camera writes and real
switch/PoE correspondence still need testing. The app and installer remain unsigned
while SignPath Foundation approval is pending, so SmartScreen warnings can remain.
