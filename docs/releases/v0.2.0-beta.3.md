# SADPTools v0.2.0-beta.3

This beta provides a newer version for testing the in-app update flow from
beta.2. Application behaviour and pinned dependencies are unchanged; the build
version advances to `0.2.0-beta.3`. It also includes the code signing policy and
records SignPath Foundation's receipt of our application. Signing approval is
still pending; this release remains unsigned.

## Test the update

1. In beta.2, open **About** and select **Check for updates**. Settings must allow
   **stable and beta** releases.
2. Select **Update now**, wait for download verification, then choose
   **Install and close**. Export any inventory or recovery data you need first;
   those live in memory. Preferences are preserved.
3. Complete setup and launch SADPTools from its Finish page or the Start menu.
4. Confirm **About** shows `0.2.0-beta.3`, then check again: this version should
   report that it is up to date.

**Starting from `SADPTools-windows-amd64.exe`?** The updater runs the installer,
which installs the app into `%LOCALAPPDATA%\Programs\SADPTools` by default (or
uses an existing registered installation). It does not replace a standalone EXE
in your Downloads folder or elsewhere. Use the new **SADPTools** Start menu
shortcut after setup; reopening the original EXE runs the old version.

Beta.1 has no updater, and `0.2.0-dev` builds cannot install releases through the
updater. Those builds require a manual upgrade to a versioned release first.

## Downloads and validation

The Windows 10/11 AMD64 installer is
**[SADPTools-0.2.0-beta.3-Setup-windows-amd64.exe](https://github.com/TerminalAddict/SADPTools/releases/download/v0.2.0-beta.3/SADPTools-0.2.0-beta.3-Setup-windows-amd64.exe)**.
It includes the same pinned offline display runtime as beta.2. Windows and Linux
AMD64 CLI archives, a build manifest and SHA-256 checksums are also included.

Release checks cover Go tests, vet and race checks, frontend tests/build,
packaging/release-tool tests, Windows cross-compilation, embedded version
verification and installer integrity. Every uploaded asset is downloaded and
verified before publication.

Windows shutdown, installation, replacement and relaunch still require runtime
testing, including this standalone-to-installed transition. SmartScreen may
still warn because the application and setup are unsigned. No new physical
camera tests or writes are part of this release; activation, network changes
and password recovery retain their existing firmware and validation limits.

See the [update guide](https://github.com/TerminalAddict/SADPTools/blob/v0.2.0-beta.3/docs/updates.md)
and [device-management guide](https://github.com/TerminalAddict/SADPTools/blob/v0.2.0-beta.3/docs/device-management.md).
