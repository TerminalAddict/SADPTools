# SADPTools v1.0.3 — network configuration and security questions

Corrects authenticated SADP network updates and adds security-question setup,
including a follow-on step after single-camera activation.

- **DHCP and static network configuration:** checks the camera's current
  authentication requirements, sends the supported authenticated request and
  preserves its unrelated HTTP/IPv6 settings. Handles acknowledgements without
  a MAC only when they match the verified transaction, and recognises password
  errors, lockouts and inactive-device responses.
- **Security-question setup:** choose three questions and save encrypted answers
  using the current admin password. Available from Device details on compatible
  active cameras. Replacing existing questions requires explicit confirmation.
- **Activation workflow:** after acknowledged activation, the app opens question
  setup on the same adapter and temporarily carries the password into the form.
  Saving requires a separate click; **Set up later** skips setup. Passwords and
  answers clear when submitted, skipped or closed and are not stored in settings,
  inventory or logs.
- **Readback and clear outcomes:** after acknowledged question setup, the app
  checks which three question IDs the camera reports configured. It never resets
  a password to test the answers. Missing replies remain unconfirmed and writes
  are never retried automatically.
- **Recovery guidance:** legacy support-code formats are now clearly identified
  as experimental and unverified for modern encrypted firmware. Existing
  HTTP(S) security-question recovery remains a separate workflow.

## Downloads and upgrading

For the standalone Windows app, download
**SADPTools-1.0.3-standalone-windows-amd64.zip**, close the running app, extract the
ZIP and open **SADPTools-windows-amd64.exe**. Saved sites and protected credentials
remain in the user's configuration directory.

For installed copies or new Windows computers, use
**SADPTools-1.0.3-Setup-windows-amd64.exe**, which includes the offline display
runtime. The in-app update checker can also install this release.

Linux DEB, RPM and manual installers, universal Apple Silicon + Intel Mac ZIP
and DMG packages, Windows/Linux CLI archives, checksums and build provenance
are included.

## Validation and compatibility

The user reported successful activation after v1.0.2. Read-only investigation of
an IPC-B261H-MU running V5.7.1 build 220610 confirmed the network authentication
profile and, after its reset, advertised security-question support with the
original 15-question list. Real metadata passed the production parsers. No
credentials or private captures are included in the source or release.

**Security-question saving and subsequent password recovery still require a
physical-camera field test.** Network lease acquisition, login and other firmware
profiles also need device-specific verification. No camera configuration writes
were performed by the development agent during this work.

The supported SADP setup profile uses question IDs 1–15, current admin passwords
up to 16 UTF-8 bytes and answers up to 128 UTF-8 bytes. Unknown/custom question
profiles are rejected. Setup uses local SADP multicast and can work outside the
host's IP subnet on the same Layer 2 network; it does not provide routed remote
setup. HTTP(S) recovery has its own reachability and compatibility requirements.

Checks cover Go tests/vet/race, 46 frontend tests, synthetic encrypted transaction
and failure tests, mocked light/dark browser flows, Windows/Linux packaging,
native Windows/Apple Silicon/Intel CI, universal Mac bundle validation and
SHA-256 verification of every uploaded asset. Compilation and synthetic success
replies are separate from real GUI and camera testing.

Windows binaries remain unsigned; Mac bundles use ad-hoc signatures without
notarization. An unconfirmed result never proves that a device stayed unchanged.
