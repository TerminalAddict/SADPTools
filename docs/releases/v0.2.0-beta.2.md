# SADPTools v0.2.0-beta.2

This beta adds in-app updates and version/update controls in About.

## Download and upgrade

**Windows 10/11, Intel/AMD 64-bit:** download
**[SADPTools-0.2.0-beta.2-Setup-windows-amd64.exe](https://github.com/TerminalAddict/SADPTools/releases/download/v0.2.0-beta.2/SADPTools-0.2.0-beta.2-Setup-windows-amd64.exe)**.
Close SADPTools, run setup, then launch the app. The installer includes everything
needed for the interface and works offline. Existing preferences are preserved.

**Coming from beta.1? Install this release manually once.** Beta.1 does not contain
an update checker. After this upgrade, future releases can be checked and
downloaded from inside the app.

Windows and Linux AMD64 CLI archives, SHA-256 checksums and a build manifest are
also included. CLI users should replace their extracted CLI with the new archive;
the desktop updater does not update standalone CLI installations.

## Changes since beta.1

- **About** prominently displays the running version and live update status.
  **Check for updates** checks GitHub manually. On Windows, **Update now** downloads
  a newer release and opens the installation confirmation screen.
- The **Updates** screen checks published GitHub releases, downloads the complete
  Windows installer, verifies its size and SHA-256, and supports cancellation.
  Only newer versions are offered; downloads and installation require a click.
- Settings include optional startup checks and stable/beta release channels.
  Beta builds default to stable and beta releases. No GitHub account is required,
  and update requests do not include device inventory or credentials.
- **Install and close** starts setup and closes SADPTools. Setup waits for the old
  process to exit before replacing the executable and offers to restart the app
  on its Finish page. Installation is blocked during an active device operation.
  Export any inventory or recovery data you need before closing the app.
- Linux desktop builds can check for releases and open release notes. Linux
  desktop upgrades still require building from source; the downloadable Linux
  archive is the standalone CLI.

## Validation and beta limitations

- Automated Go tests, vet and race checks; ten frontend tests; installer-input
  and release-tool tests; Windows cross-compilation; and installer archive and
  checksum verification are part of the release checks.
- The Linux GUI was inspected under Xvfb in dark/light themes with isolated
  preferences. Real GitHub checks and a verified release download were exercised
  on Linux. These checks do not establish Windows installation behaviour.
- **Windows installation, application shutdown/replacement/relaunch, clean
  offline runtime setup, antivirus/file-lock behaviour and firewall/adapter
  handling still need testing on Windows.** The app and installer remain unsigned.
  The bundled Microsoft runtime is unchanged from beta.1; its Authenticode
  verification remains a Windows check.
- Basic discovery was previously exercised with physical Hikvision devices on
  Linux, including an inactive camera. Activation, network changes and password
  recovery still need physical-device/firmware validation; no new camera writes
  were performed for this release. A timeout does not prove a device was unchanged.
- Password recovery requires a valid vendor/support code. Vendor XML/GUID/email
  recovery, encrypted command variants, firmware upgrades and batch operations
  remain outside this beta.

See the [update guide](https://github.com/TerminalAddict/SADPTools/blob/v0.2.0-beta.2/docs/updates.md)

Report reproducible problems through [GitHub Issues](https://github.com/TerminalAddict/SADPTools/issues)
