# SADPTools v1.0.0 — First stable release

SADPTools is a cross-platform camera discovery, site management and commissioning
utility for Windows, Linux and Apple Mac. This first stable release brings the
existing technician toolkit together with portable site transfers and improved
Live View support for imported cameras.

## Downloads

- **Windows 10/11 AMD64:** `SADPTools-1.0.0-Setup-windows-amd64.exe` includes the
  offline WebView2 runtime and installs a Start-menu shortcut.
- **Windows standalone desktop:** `SADPTools-1.0.0-standalone-windows-amd64.zip`;
  extract and run `SADPTools-windows-amd64.exe`. WebView2 must already be installed.
- **Linux AMD64:** DEB, RPM and manual `install.sh` packages include the desktop
  app, CLI, application-menu entry and icons. GTK4/WebKitGTK runtime requirements
  are documented in the Linux installation guide.
- **Apple Silicon and Intel Mac:** universal `.dmg` and `.zip` app bundles.
- Separate Windows and Linux CLI archives, plus `SHA256SUMS` and a build manifest.

## Changes since release candidate 2

### Move complete sites between computers

**Export site** creates a passphrase-protected `.sadpsite` containing the saved
inventory, known camera credentials, credential assignments, site documents,
attachments and history. **Import site** previews the contents and creates a new
site, remapping references and encrypting credentials for the destination laptop.
Existing sites are retained. Ordinary **Export report** remains separate and
excludes credentials.

Import also accepts NX Camera Info JSON exports and the documented versioned
SADPTools site JSON format. Known/revealed passwords are carried into the vault;
masked or unavailable passwords remain unknown. Source-laptop adapter bindings
are cleared so scans use an adapter selected on the destination computer.

### Live View for imported cameras

NX stream addresses are now retained as encrypted attachments and selected
when Live View opens. Previously they were discarded and cameras without ONVIF
advertisements incorrectly defaulted to a Hikvision RTSP path. Saved streams
prefer the exported sub stream when present; authentication failures are not
retried automatically. URLs, tokens and passwords stay out of frontend metadata,
ordinary reports and logs.

**Re-import an earlier NX export into a new site to gain its saved stream
addresses.** Previously imported sites cannot recover information that was
already discarded. Open Live View from the newly imported site.

The ONVIF service check now treats an explicit HTTP port 80 or HTTPS port 443 as
equivalent to its omitted default. Different hosts, schemes and other ports
remain restricted. This resolves the observed Milesight profile-discovery error.

### Existing toolkit

The release retains SADP and ONVIF discovery, routed-camera investigation,
HTTP/HTTPS web-interface detection, activation and supported network/recovery
operations, site inventories and credential vaults, NVR channel mapping,
independent Live View windows, stream diagnostics, focus/alignment tools,
supported PTZ controls, health audits, switch inspection, site plans,
commissioning evidence and reporting. Unknown or unsupported device capabilities
remain explicit; model-specific write operations require deliberate selection.

## Validation

- Go tests, vet and race checks; frontend tests and production builds; release
  and platform-packaging tests; browser checks for import/export and automatic
  Live View source selection in light and dark themes.
- Windows installer/standalone and Linux desktop/CLI/package builds, installer
  integrity checks and embedded-version verification.
- Native GitHub Actions checks on Windows, Linux, Apple Silicon and Intel macOS;
  universal Mac bundle, signature/plist and DMG validation.
- All release assets are downloaded from the draft and checked against the local
  SHA-256 manifest before publication.

Read-only hardware checks on Sparx verified imported-camera playback for the
user-identified Grandstream GDS3727, Milesight MS-C2964-RFLPE and Tapo C100. Each
produced at least 25 displayed frames through the native streaming engine and
Linux Chromium player. Milesight and Tapo also returned ONVIF main/sub profiles.
No camera configuration was changed and no footage was recorded. This evidence
is specific to those cameras and their current firmware/settings.

## Compatibility and testing limits

Windows binaries remain unsigned and may trigger SmartScreen; stable release
status does not add a signing certificate. Mac bundles use ad-hoc signatures and
are not Developer ID signed or notarized; Gatekeeper may require an explicit
user override. See the signing and macOS installation guides.

Windows WebView2 playback, real laptop-to-laptop vault transfers, physical Mac
permissions/adapters/Live View, long-running streams and additional camera
firmware still need field testing. macOS updates use manual app replacement;
the existing verified Windows installer/standalone update process is retained.
RTSP uses TCP; UDP video transport is unavailable. Firmware uploads, automatic
replacement provisioning, privacy-mask editing and verified replay retrieval
remain unavailable. Uncertain camera-write outcomes are never retried
implicitly.
