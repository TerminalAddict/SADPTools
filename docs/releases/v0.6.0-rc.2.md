# SADPTools v0.6.0-rc.2 — Release candidate 2

This release adds macOS build and platform support to the existing v0.6 toolkit,
using the same Go backend and Wails v3 interface. Windows and Linux downloads
remain available. This is a test release; native builds and synthetic tests do
not establish compatibility with every camera, network or desktop configuration.

## Downloads

- **Windows setup:** `SADPTools-0.6.0-rc.2-Setup-windows-amd64.exe`, including the offline display runtime.
- **Windows standalone:** `SADPTools-0.6.0-rc.2-standalone-windows-amd64.zip`. Extract and run the EXE using an existing WebView2 runtime.
- **Linux:** DEB, RPM and manual tar.gz installers, including desktop app, CLI and application-menu integration.
- **macOS:** `SADPTools-0.6.0-rc.2-macos-universal.dmg` or `SADPTools-0.6.0-rc.2-macos-universal.zip`. Both contain a native Apple Silicon + Intel `SADPTools.app`, targeting macOS 12 or later. Copy the app to Applications before launching.
- Separate Windows and Linux CLI archives, `SHA256SUMS` and the build manifest are attached.

**macOS test builds are ad-hoc signed, not Developer ID signed or notarized.**
Gatekeeper may require Privacy & Security → Open Anyway after an attempted launch.
Allow Local Network access when prompted. Windows binaries also remain unsigned
and can trigger SmartScreen. Neither platform's publisher warning is resolved by
this release.

## Changes since RC1

- ARM64, Intel and universal macOS targets, app bundles, ZIP/DMG packaging, the
  Signal Lens icon and a Local Network purpose description.
- macOS kernel ARP/default-gateway inspection and scoped destination-route
  diagnostics. Discovery retains the existing portable UDP engine and adapter
  handling; cached ARP remains evidence rather than proof of reachability.
- Live View explicitly permits autoplay in its separate macOS WKWebView window.
  H.264 is the first compatibility target; HEVC depends on the OS and decoder.
- Optional packet capture locates an existing Wireshark/Homebrew dumpcap on macOS
  without installing drivers or changing privileges.
- Update checks select packages for the running platform. Windows retains its
  verified installer handoff. macOS offers manual updates: quit, replace the app,
  then reopen it; saved sites and settings remain outside the app bundle.
- Native macOS CI and verified universal-artifact import into the existing
  release process. Linux Docker/Zig cross-build tooling is also included;
  Sparx still needs Docker access and a privately supplied macOS SDK.
- Correct target-architecture forwarding through Wails tasks and repeatable
  copying of read-only generated licence files during Windows builds.

The macOS credential vault uses the existing encrypted master-passphrase mode;
Windows DPAPI behaviour is unchanged. Keychain auto-unlock and automatic Mac app
replacement are not implemented. No camera protocol/backend was duplicated.

## Validation and release gates

Release publication requires Go tests, vet and race checks; frontend tests and a
production build; packaging/release-tool tests; Windows setup/standalone and
Linux desktop/CLI/package builds; installer integrity and embedded-version checks.
Native macOS CI must produce both Mach-O slices, validate the app's ad-hoc
signature and plist, create/verify/mount the DMG, and pass desktop service tests.
Mac artifacts must match this release's clean source commit and version.
Every published asset is downloaded and SHA-256 verified before publication.

## Hardware and runtime testing still needed

- Actual Apple Silicon and Intel Macs: Finder/Dock/Retina, Gatekeeper, Local
  Network/firewall permissions, adapters, multicast, routes/ARP, browser and file
  dialogs, saved sites/vaults, Live View codecs/autoplay/window lifecycle, and
  manual upgrade preservation. macOS 12 is a deployment floor, not a tested
  promise for every feature/codec.
- Windows launch, installer/standalone upgrades from RC1, WebView2 and Live View;
  Linux installation/removal on supported distributions outside the build host.
- Real-camera activation, network configuration, recovery and other writes on
  explicitly authorized test devices. No new hardware test or camera write was
  performed for RC2. RC1's recorded read-only Linux camera evidence remains
  limited to that earlier application and hardware configuration.

See the [macOS guide](https://github.com/TerminalAddict/SADPTools/blob/v0.6.0-rc.2/docs/macos.md)
and [v0.6 compatibility guide](https://github.com/TerminalAddict/SADPTools/blob/v0.6.0-rc.2/docs/v0.6-diagnostics.md).
Firmware uploads, automatic replacement provisioning, privacy-mask editing and
verified replay retrieval remain unavailable. Uncertain camera-write outcomes
are never automatically retried.
